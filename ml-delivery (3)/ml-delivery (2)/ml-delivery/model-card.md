# Model Card — Synthetic Academic Support Review Prototype

## Intended use
Demonstrate a reproducible ML pipeline that estimates whether a student's future week-9 DSA assessment score will be below the configurable prototype threshold of 50/100, based only on historical weeks 1–8 observations. A review signal may help a human mentor inspect evidence.

## Out of scope
Not a dropout predictor, psychological or clinical diagnostic tool, causal model, automatic intervention decision, punishment mechanism, or validated production system.

## Data
Fictional generated longitudinal records for 1,500 students, eight weekly historical records per student, DSA subject, separate week-9 outcomes and separate synthetic audit metadata. The generator includes stable, declining, improving and attendance-decline profiles; cohort variation; noise; missing recent values; and unpredictable outcome noise. These are explicit modeling assumptions, not empirical facts.

## Features
Recent score mean, score trend, recent attendance rate, attendance change, assignment completion rate, recent LMS active-day mean, observation count, missingness indicators and structured academic concern count. Student IDs and cohort IDs are excluded from the feature matrix. Audit metadata is separate.

## Method
Student-level 70/15/15 split. Preprocessing is fit inside a scikit-learn pipeline on training data. Model and decision threshold are selected using validation data. The held-out test set is used for final evaluation only. Actual metrics are generated by `scripts/train.py` and saved to `reports/metrics.json`.

## Missing data
No missing records are fabricated. Numeric features are imputed by a training-fitted median imputer; missing indicators are added by scikit-learn. If fewer than four observation records exist, prediction returns `insufficient_data` and a null model score.

## Limitations
Synthetic evaluation does not establish real-world performance, calibration, fairness, or intervention effectiveness. Random student split does not reproduce future-term deployment. Real deployment requires temporal validation, external validation, stakeholder review, privacy/security controls, and human oversight.

## Appropriate use
Prototype demonstrations, pipeline engineering, schema integration, and test development.

## Inappropriate use
High-stakes decisions about individual students, automatic sanctions, diagnosis, inferring family/financial/medical causes, or claims of proven fairness.
